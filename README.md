# textbook-full-workflow

> 面向任意学科教材的 **全流程学习技能**（Agent Skill）：从电子书获取 → 扫描版 OCR → 复习资料产出。
>
> 三种输入自动路由：**只给书名**→从正规公开渠道下载电子书；**给扫描版 PDF**（无文本层）→macOS Vision 框架 OCR 识别全文；**给带文本层的 PDF**→直接提取。产出**排版精良的 PDF**：一份《全书知识点与公式背诵合集》（纯知识点，供背诵复习），一份《自学教学文档》（书上完整原题 + 分步带做解析，供自学解题）——全部公式 LaTeX 专业排版、每页带署名水印、交付前强制程序化校对。
>
> 作者：**TiantianYe**
>
> 作者在 App Store 中的其他代表作品：水课帮-课堂提问助手；识词本-单词笔记；投影与视图3D教具；解构照片；实验数据拟合

## ✨ 这是什么

`textbook-full-workflow` 是一个 Agent Skill（智能体技能包），把"从一本书名/一本教材 PDF 产出高质量复习 PDF"的**完整全流程**沉淀为可复用的工作流、脚本与踩坑经验。

它解决的问题非常具体：

- **书没有电子版怎么办**——技能内置正规渠道检索与下载工作流（高校公开教学资源、出版社官方渠道、验证码附件系统处理、下载验真），不用盗版站点；
- **书是扫描版怎么办**——纯扫描 PDF 无文本层，内置 macOS Vision 框架中文 OCR 脚本（实测 386 页中文书 150 秒识别 23 万字），识别后规范化为与文本层提取一致的格式；
- **手工整理知识点**——耗时且容易遗漏；直接让 AI"总结一下"则常混入书外内容、公式显示为乱码或纯文本；
- **数学类教材的公式**——在 Markdown/网页里经常渲染不出来（裸露 LaTeX 源码），只有排版成 PDF 才有复习价值；
- **网上的复习资料不可溯源**——本技能强制**每一条知识点、每一道例题都能在原书中检索到**，且交付前对**每一个数字做程序化复算/批量溯源核对**。

两份产出物：

| 产出 | 内容 | 用途 |
|---|---|---|
| 《书名 · 背诵合集.pdf》 | 全部定义/定理/公式 + 汇总速查表（理科）/大事年表（文科）+ 易混淆速记 | 背诵复习，不掺杂任何无关信息 |
| 《书名 · 教学文档.pdf》 | 书上完整原题 → 分析 → 第 1 步/第 2 步分步带做 → 方法总结 | 自学解题，看步骤就能学会 |

> 用户明确只要其中一份时，按用户要求交付一份。

## 🎯 使用场景

| 要素 | 说明 |
|---|---|
| 输入材料 | ①只给书名（自动下载）；②扫描版教材 PDF（自动 OCR）；③带文本层的教材 PDF（直接提取）。数学/统计类已实测，历史/政治等文科同样适用 |
| 产出要求 | 复习 PDF：背诵合集 + 教学文档；公式 LaTeX 排版 |
| 质量要求 | 内容全部溯源原书、严禁编造；交付前数值全部程序化校验 |

典型触发指令示例：

> 帮我下载《改革开放简史》电子书，然后做一份核心知识点背诵 PDF 用于期末复习。
>
> 这是一本《XX》教科书PDF，请仔细阅读，所有知识参考都需要来自这本书、严禁摘取其他未经证实的信息。帮我做2份PDF：一份为核心公式、知识点的背诵合集（包含全书全部知识点和公式，供背诵复习，不允许掺杂无关信息）；一份为自学教学文档（包含书上例题及详细解题步骤，能教会我解题）。每一页PDF上方都要有"Designed by TiantianYe"的水印，所有公式用LaTeX排版，输出前务必严格校对。

将本仓库克隆（或复制 `textbook-full-workflow/` 文件夹）到 Agent 技能目录：

## 🚀 使用方法（工作流概览）

技能按 8 个阶段自动执行，完整细节见 [SKILL.md](SKILL.md)：

| 阶段 | 内容 | 关键点 |
|---|---|---|
| 0. 输入分诊 | 判定输入三态：只有书名 / 带文本层 PDF / 扫描版 PDF | 决定路由 |
| 1. 电子书获取 | 正规渠道搜索 → 附件解析 → 验证码下载 → 三步验真（仅态 A） | 详见 references/download-guide.md |
| 2. 原书全文 | extract_book.py（文本层）/ ocr_book.py + macOS Vision OCR（扫描版） | OCR 后必须抽检 |
| 3. 撰写两份 md | 按定稿模板写背诵合集与教学文档 | 例题必须能溯源原书；题目完整、解析分步带做 |
| 4. 强制校对 | 理科数值复算 / 文科批量溯源核对；bare_math_scan.py 裸数学归零 | 两道关卡全过才准进入构建 |
| 5. 构建 HTML | build_pdfs.mjs（KaTeX 占位符方案） | 数学式在 Markdown 解析后才放回 |
| 6. 打印 PDF | Chrome headless（必带 `--no-pdf-header-footer`） | 控制台 `KATEX_ERROR` 必须为零 |
| 7. 水印+终验 | watermark_verify.py 四项验证（水印/超界/残留/页数） | 退出码 0 才可交付 |
| 8. 交付 | 只交付按用户要求确定份数的 PDF | 注明电子书来源渠道 |

## 🔧 环境依赖

- **Python 3** + `pymupdf`（提取、水印、验证）
- **Node.js**（任意近版本）+ `marked` + `katex`（HTML 构建，`npm install marked katex`）
- **Google Chrome**（headless 打印 PDF）
- **Xcode Command Line Tools**（仅扫描版 OCR 需要，`swiftc` 编译 Vision OCR 脚本；无 swiftc 时降级方案见 SKILL.md）
- 路径可用环境变量覆盖：`MARKED_PATH`、`KATEX_PATH`（见 `scripts/build_pdfs.mjs` 头部适配指南）

## ⚠️ 重要说明

- **内容溯源是红线**：所有知识点与例题必须来自电子书，技能内置"原书溯源检索"工序；检索不到原题的例题会被替换为书中原题。
- **原书也会错**：校对发现原书印刷/计算错误时，产出物采信正确值并加注说明。
- **严禁跳过校对**：数值校验、裸数学扫描、PDF 四项验证任一未通过都不得交付。
- **电子书只走正规公开渠道**：高校公开教学资源页、出版社官方、正规电子书平台；盗版站点一律不碰，来源渠道写入交付说明。
- **扫描版先 OCR 并抽检**：OCR 产物经人工抽检合格后才进入精读撰写；关键数字以溯源核对兜底。

## 🐛 已知踩坑点

以下是项目实测踩过的坑，全部已沉淀为脚本内置逻辑或校验规则（完整档案见 [references/format-rules-and-errors.md](references/format-rules-and-errors.md)）：

1. **绝不要把 LaTeX 转成 Unicode 直排**（X̄、σ² 这类"看起来能读"的写法）。用户要 LaTeX 就是为了 PDF 渲染清晰；md 裸读难看的正解是交付渲染后的 PDF。
2. **扫描版教材的数字是全角+私用区编码**：小数点、带分数提取后会失真（如原书 1¾ 提取成 13/4），必须先规范化再核对，且靠程序化校验兜底。
3. **KaTeX 必须用占位符方案**：把含 `$...$` 的 md 直接喂给 Markdown 解析器，`\{` 的反斜杠被吃、`_` `*` 被当斜体，公式全碎。
4. **Chrome 打印必带 `--no-pdf-header-footer`**，否则页眉页脚污染版面。
5. **PDF 溢出检测别用 DOM 测量**（公式容器宽度全不可靠），要在打印结果上用 pymupdf 检查文本块右沿。
6. **Python `\U` 转义必须正好 8 位十六进制**：`\U0001001b0` 是错误写法（9 位），映射永不生效且不报错。
7. **表格内绝对值要写 `\|` 转义**；`~~` 会渲染成删除线。
8. **给命令映射表加短命令前，先检查是否存在以它为前缀的更长命令**（`\big` 会截断 `\bigcup`）。
9. **每章另起页但首页不能空白**：教学文档第一章需紧随引言（`h1:nth-of-type(2) { break-before: auto; }`）。
10. **人工通读抓不到数值错误**：理科 5 处计算/提取错误全部由程序复算发现；文科同样必须程序化批量溯源核对（grep 到原书全文）。
11. **文科文档用全角括号**：`GDP(...)` 这类半角括号紧跟字母会触发裸数学扫描的函数记号误报。
12. **高校 CMS 验证码下载要全程同一会话 cookie**：请求验证码图与最终下载必须携带同一 cookie 罐，否则验证码校验永远失败。
13. **下载体积即真相**：只有几 KB 且 `file` 显示 HTML，说明拿到的是验证码页/错误页，不是书。
